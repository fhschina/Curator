## 剩余问题的准确位置

`actual_membership_conflict:ba`：A的完整排他名单为甲、乙、丙，B为甲、乙。
模型三次都理解闭合名单冲突、填写双侧UNCOVERED，但证据槽位稳定填错：

| 槽位 | 实际三次填写 | 本例可验证的配对 |
| --- | --- | --- |
| A-in-B source / counterpart | S001 / A001 | A001 / S001 |
| B-in-A source / counterpart | S001 / A001 | S001 / A001 |
| hard_conflict A / B | S001 / S001 | A001 / S001 |

第一行的counterpart必须属于B，却选了A_ONLY；根证据两侧又只选相同的共享前缀。
校验首先返回 `CONTEXT_DIFFERENCE_REQUIRED`，不能因为自由文本解释提及A001就自动替换结构化证据。
这与 `.30` 原先无法表达短侧共享上下文不同：新契约能表达两个方向，离线与本地真实链路已验证；
本次线上模型在反向输入中仍混淆证据槽位。正向一次成功不能证明镜像稳定性。

下一项应聚焦本侧source/对侧counterpart的ID约束、镜像绑定和具体纠错反馈，减少重复证据字段的
一致性负担；不要再改“独立Y可containment”的语义口径，不自动修补已观察的响应，也不放松实际差异要求。
任何新候选都需新冻结、新run；当前 `.31` 不重启。没有完整main/critic面板，不发布critic净收益、
版本语义排名或75%达标结论，不扩大到1000/20,000条。
