# Conditional full original development diagnostic

This protocol is written before any new full-development candidate output is observed.
Its purpose is to measure the real weighted bottleneck on all original 1,000 inputs,
not to promote a selected 96-case score, release a version or replace disputed gold.

Admission requires a completed two-repeat 96-case paired repair, every observed
cross-arm error reviewed against actual source, and zero candidate engineering or
clear target/guard failures in both repeats. Any remaining repeat variation must be
explicitly reviewed as a pending policy question. The exact reviewed decision must
say FULL1000_DIAGNOSTIC_NOT_RELEASE. V4 fails this criterion and cannot be expanded.
Old pilot gates containing pending H0701/H0760 remain unchanged and failed; this is
a separate, explicitly non-promotional population diagnosis under the user's five-hour
iteration request, not a claim that those old gates passed.

Freeze the latest eligible critic unchanged. Replay all .12 raw main outputs and the
same v6-route. Fresh original .12 critic is the online control; historical .12 main/final
are separately scored saved baselines. All 250 positive, non-exact mains receive fresh
calls in both arms; 738 negative/unresolved and twelve exact cases bypass. One repeat,
500 planned critic calls, zero main calls. Never splice selected prior responses into
the full population or retry a schema/semantic answer. Every prior local request must
be byte-identical. Same model, generation, strict-schema candidate and pacing.
If the eligible candidate changes schema property order, preserve its order-sensitive
frozen request string and verify actual output order; do not silently canonicalize
the candidate back to the old generation order in the full run.

Preserve historical and partial-policy-v2 references, all 1,000 rows and all weights.
Report weighted/unweighted P/R and primary agreement, missing outputs as unresolved,
guard failures, fresh/saved baseline differences and cause weights for every error.
Pending disputes remain in the score. No reinterpretation of faithful translation's
old material taxonomy enters primary version selection.

The user target is complete full-population weighted P and R each at least 75%.
Report primary agreement at least 79%, guard protection and engineering status separately;
passing the user's development target never implies release or holdout validity.
Every observed cross-arm error is reviewed before another candidate. A failed run may
guide one cause-led repair but cannot be relabeled into a pass. Hard deadline remains
2026-09-11 12:00:52 UTC, with new-call admission stopped 210 seconds beforehand.
