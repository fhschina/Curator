## 主要瓶颈：模板被当成实质 X，critic 基本没有修正

156 个误合并中 **134 个 CONTAINMENT、22 个 NEAR_SURFACE**。
false containment 占误合并权重的约 86.90%，critic 没有减少其条数。
按冻结参考原因分解误合并：

| 参考类别 | 误合并条数 | 加权误合并量 |
| --- | ---: | ---: |
| meaningful_addition | 59 | 604.49 |
| boilerplate_only | 41 | 456.95 |
| page_role | 22 | 232.58 |
| identity_slot | 13 | 117.49 |
| material_content | 11 | 109.71 |
| factual_state | 8 | 56.62 |
| list_membership | 2 | 18.61 |

所有 156 个误合并的模型 certificate 都选择了 `SHARED_SUBSTANTIVE_CONTENT`。
但模型自己的 dominant overlap 中，42 个是 COOKIE_CONSENT、29 个 LEGAL_POLICY_TEMPLATE、
27 个 SHARED_PAGE_TEMPLATE、2 个 ERROR_AUTH_PAYWALL、1 个 SITE_CHROME；仅 55 个为 MAIN_CONTENT。
这些字段是模型的声明，不是新的人工真值；不能据此简单否决所有“模板占比高但确有正文 X”的正例。

以下为查看预测后的诊断抽查，不是独立盲审，未修改任何标签：

- **H0360**：A 只有西班牙语 cookie／隐私说明，B 增加项目正文。主 Judge 明确把标准 cookie 同意说明
  命名为“实质 X”，并据此判 containment；critic 原样保留这个核心理由。
- **H0266**：A 是信贷条款与免责声明，B 增加家庭安防摄像头文章。两阶段都把共享免责声明视作 X。
  这正是原政策已经排除的“文章 + 通用免责声明 vs 免责声明”边界，不是独立 Y 政策允许的正例。
- **H0946**：通用相框文案与具体相框页面。模型用更宽泛的类别覆盖具体类别，并把具体产品与操作说明
  视为新增 Y。这类案例还需分别核实真实正文锚点、页面功能和列表项是否保留，不能仅按参考类别直接改规则。

当前实际 prompt 已明确说 cookie banner、导航、通用运输／免责声明本身不是 X，且包含两个对应负例。
所以这不是缺少一句排除规则；真实长文本上的执行与合成例子之间有明显落差。
`meaningful_addition` 中也可能包含旧口径争议，不能把全部 59 条未经复审都称为明确模型错误。

同主输出消融结果：critic 请求 **317 条**，修正 H0591、H0937 两条误合并，修正 H0432 的方向，
没有把原本正确的主决策改错；加权主决策净收益仅 **+0.286 个百分点**。
有 **158/317** 个完整 certificate 与主 Judge 相同，**300/317（94.64%）**个 `basis_explanation` 逐字相同。
这说明当前 critic 的实测独立纠错作用很弱；文本重复本身不证明模型内部因果机制。

## 建议的下一步与追溯

不晋级 `.32`，不扩到 20,000，不读取 holdout，不放宽 75% 门槛，不改标签来提高分数。
保留用户已确认的“**实质 X + 独立 Y**”规则。下一轮只隔离两个问题：

1. 独立验证共享 X 是否为正文，并在真实 cookie／免责声明／模板样本上保护非空 gate；
   同时保护真正的正文 X+Y、完整翻译和普通 chrome 等价，不能按 overlap 标签一刀切。
2. 做小规模 critic 输入消融，例如不展示主 Judge 的理由、先独立判断 X，再比较覆盖结论；
   检验是否减少实测复述。更强模型可作为后续诊断对照，不能在本轮未经固定协议就替换模型。
