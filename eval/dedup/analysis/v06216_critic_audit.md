## 两个目标：标签和理由必须分开看

**H0347：同意条件补丁只在 R2 修好，R1 仍误判 no/no。**

- 可见 A、B 都明确保留“继续浏览即同意”；B 另有 Accetta 按钮。
- consent R1 即使被明确要求对齐完整条件，仍把 B 的按钮解释为 explicit-only，输出 policy_permission_change。
- consent R2 才正确对应 A001 与 B002 的继续浏览句义，认为额外按钮没有改变该条件。
- control 两轮的最终标签都是 yes/yes，但 R1 理由仍称 A/B 是 implied/explicit 的差异，继而错误地把这种差异泛化为良性 UI。
  因此 control 标签正确不等于它稳定理解了真实条件，更不能据此放宽真正的权限变化。

**H0748：短指针补丁两轮都没修好。**

- 可见 B001 只有 Stories...Casey-Lee Lyons，没有文章正文或人物事实。
- pointer 两轮仍将其当成具体 story/author record，输出 generic_context_only + separate_record_or_template_attachment。
- R1 甚至用“按照边界示例”的措辞支持分离，与实际 prompt 的短指针说明相反。
  加说明不等于模型会可靠执行，也不能靠更多出现一次的案例说明宣布修复。

H0453 与 H0347 的完整可见 payload 逐字相同，参照同为双向等价；consent R2 却分别判为 no/no 与 yes/yes。
H0453 的理由承认 B 也可能表达继续浏览同意，最终仍凭按钮推测不同的法律/交互状态。
这说明同意条件补丁的单次目标命中不足以支持“已修好”。本审计没有采纳这些模型法律推断。

原始双侧文本、偏移、三个字段理由与最终输出见 [响应归因](v06216_response_attribution.json)。
