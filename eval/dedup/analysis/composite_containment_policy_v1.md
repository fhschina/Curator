# 复合文档 containment：已确认的口径修订 v1

状态：2026-09-10 用户确认；适用于后续标注和新候选设计。不是模型发布，也不是已部署的 runtime。

> 允许“X＋独立的 Y”对“X”构成单向 containment，不再把它限定为“同一具体记录的扩展”。

这一决定取代[瓶颈仲裁清单](bottleneck_arbitration_v1.md)中 P1「记录单位」的二选一待办，
也取代此前开发复核中**仅因 Y 是独立记录而否决 containment**的建议。
旧建议、旧标签、旧模型输出和旧分数均保留作为历史，不回写它们来制造提升。

## 新规则

1. 先识别两侧真正保留的实质内容。X 必须非空，并在两侧有可核对的内容锚点；
   只共享 cookie、导航、通用免责声明或配送模板，不足以证明 X。
2. A = X + Y、B = X 时，只要 A 完整保留 B 的应保留含义、Y 确有未被 B 保留的实质内容，
   且没有下述实际冲突，则 `A can replace B = YES`、`B can replace A = NO`、
   `same_duplicate_group = YES`、`relation = CONTAINMENT`、`material = MAJOR`、
   `primary material difference = MAIN_CONTENT_ADDITION_DELETION`。
3. Y 可以是另一篇文章、另一项机会或独立介绍；不要求 Y 的具体记录核心已出现在 B 中。
   应证明的是共享的 **X**，不是要求新增的 **Y** 也已被对侧介绍。
4. 若 Y 只是普通按钮、导航、重排、复述或已被覆盖的同义内容，则不是 containment；
   X 完整相同时仍是双向可替代。完整忠实翻译继续双向可替代，语义 material 为 NONE。
5. 真正的身份/服务对象、字段值、状态、页面角色或列表快照成员冲突仍可否决替代。
   新增独立 Y 的名字、标题或主题本身不是 X 的身份冲突；「多了一个内容板块」也不自动构成角色冲突。
   不得用旧的单记录限制改名成 page-role veto，把本次放宽全部抵消。
6. A = X + Y、B = X + Z，且 Y/Z 各有不能被对侧保留的实质内容时，仍是 no/no。
   文本更长、字符包含、同站点或同模板都不能单独证明语义替代。
7. 输入不足、X 的正文属性或必要方向无法核验时保留待核/未决；不凭字面子串关系补出证据。
   截断输入、证据对齐与公开 v3 输出一致性要求不放宽。

本次没有统一全部 non-main 消息的等价边界，也没有裁定裸标题、姓名片段、文件名或
独立政策正文与通用政策模板的所有边界。特定日期/对象的闭馆通知不能仅因重复展示就视为 cookie 类噪声；
反过来，法律或配送文字也不能仅因短页只剩这些内容，就自动升为共享正文。

## 成对回归材料

[机器可读材料](composite_containment_review_v1.json)包含独立 Y 扩展、同记录字段增补、两侧独有正文、
chrome、cookie/免责声明空锚点、实际 SKU/状态/角色/列表冲突、完整翻译、等价 non-main 和截断输入。
导出时为每条自动生成 A/B 镜像，检查替代方向也随之交换。

这些是**合成的政策预期**，不是模型已通过的语义测试；离线单元测试只验证材料的输出契约、方向、
匿名隔离和原文证据，不能证明当前模型理解了新规则。

这批来自上一轮 `.12` 的 `record_unit` 错误簇，不代表完整 1,000 条里所有可能受影响的样本。
以下是预测可见的 AI 开发复核，不是独立人工仲裁；规则获批不等于每条 gold 获批。

| 分组 | 样本 | 处理 |
|---|---|---|
| 清楚符合复合包含 | H0822、H0521 | 分别为 A→B、B→A；旧参照已是同方向 containment，不改标签 |
| 仍须核验非空正文门槛 | H0208、H0492、H0672、H0957、H0998 | 共享配送/平台/保修内容是否仅模板，不能因新规则批量恢复正例 |
| 还有其他边界 | 其余 12 条 | 分开记录正文属性、具体主体、字段覆盖、真实列表/角色或权限含义问题，不强制二选一 |

H0822 两侧都完整保留 UAL Top Drawer 申请及折扣展位说明，A 另有志愿者/实习机会；
H0521 两侧保留同一图书馆 2025 闭馆时间、预约限制和服务说明，B 另有科幻馆藏介绍。
这里 Y 的独立性不再是拒绝理由。

H0320 还增加具体联系人，H0787/H0926 涉及推荐文章段落，H0540 涉及网站历史/方法介绍：
应核对共享内容的实质性与真正保留的角色/集合含义，不能再仅以「不是新增记录的正文」否决。
H0132、H0666 原参照是负例，同样纳入检查，不能只复审有利于召回的旧正例。

已保存的 `.12` 输出显示：H0822 主 Judge 已经判 no/no；H0521 主 Judge 给出正确 B→A，
最终被 critic/adapter 否决为 no/no。这说明同一政策修订同时涉及主判断与后置检查的职责，
不是只要放开 critic 就能修好这两条。两条总权重 18.6135，不是 19 条总权重 183.9176；
这些是审计权重，不是新政策必然带来的分数提升。

## 工程与评估边界

旧 `SAME_SUBSTANTIVE_RECORD` / `DISTINCT_OR_UNBOUND` 把「没有共享 X」与「Y 是独立记录」混在一起。
因此不能把保存的 `DISTINCT_OR_UNBOUND` 自动改解释成已验证的复合包含，也不能读 critic 的自由文本猜测新证书。
旧冻结配置、adapter 和 cache 不变；当前运行入口**尚未切换**到新政策。

下一候选应在新 contract 下分别表达共享实质 X、双向保留/缺失和实际冲突；
同步改主 Judge、critic 的 system/pair/rubric 及 adapter，而非只在旧 prompt 尾部追加一句。
固定主 Judge 已判 NO 的路由不会调用 critic，这部分也必须单独核对，不能期待只改 critic 就修复全部遗漏。

本轮不生成新 reference，不重报新 P/R，不进行在线调用。离线导出保留旧主/最终判断用于定位，
只有材料检查的结果，不是代码修复或模型能力提升。
若之后产生逐条确认的新参照，所有可比历史版本必须用同一参照重算，改标效应与模型效应分开。
75% 门槛和独立 holdout 要求不变。

