# .9 / .12 / .32：相同保存输出的离线重算

2026-09-11。结论：**建议以 .12 为下一轮实验对照，保留 .9 为保守对照；暂不继续扩展 .32，也不发布新版本。**
已接受的政策规则不足以解释 .32 的退化。下一步需要分离 critic 的有益修正与误否决，而不是继续同时改主 Judge、critic 和参照。

这次完成的是历史参照重算及**部分新版参照草案的敏感性分析**，不是新的在线 benchmark，也不是完整人工重标后的正式成绩。

## 比较范围与参照边界

- 三个版本均使用原始 1,000 个 pair，逐项验证 payload 完全一致；原分层权重不变，总权重 10,023。
- 分别重放 main / final，共六个视图。.9、.12 的最终公共字段必须与原保存结果逐字段一致；.32 的主流程及最终计分结果必须与原始输出重放一致。
- .9 main 使用历史默认 `v1` 路由，final 使用 `v3`；.12 main 使用 `v6-route`，final 使用 `v6`。没有将后来修复偷偷回灌到 .9。
- .9、.12 各有 1,000 条有效输出；.32 有 997 条有效输出及 3 条终态缺失占位，全部保留在 1,000 条计分分母中。占位不是合法 Judge 结果，也不获得“正确未决”信用。
- 老参照逐字节备份并保留。它本身含历史 AI 协助修订，不能将它或本次草案重新包装为纯独立人工 gold。
- 草案仅应用上一轮已有证据的六条政策案例建议：H0108、H0126、H0419、H0590、H0869 的主决策由 NO/NO 改为单向包含；H0998 原来已是相应单向包含，不变。五条变化权重合计 **50.225**。
- 这是用户批准规则后的 **AI 实例应用**，新增独立仲裁数为 0。其他标签仍保持历史值，包括待核项；不删除争议样本、不填 U 来缩小分母。
- 仅评分同组与两个替代方向。旧 relation/material 等 taxonomy 原样保留但明确标为历史字段、不评分，避免把未重标的 taxonomy 混进新口径的主版本选择。

历史版本之间可能还存在其他执行差异；这是同输入历史对照，不是同温、同时运行的单因素 prompt 实验。

## 全量检查做了什么，尚未做什么

对全部 1,000 条输入进行了不看预测的文本筛查：较短侧非空，长侧至少增加 120 个字符，且短侧完整出现于长侧、或共有 span 字符占短侧至少 80%。
得到 **274 条增量文本候选**，含历史 NO 229 条、YES 45 条。另有 713 条未被此启发式选中，13 条不能从完整 text 字段做此检查。

这不是“274 条都是政策案例”，也不是“未选中的 726 条已证明不受口径影响”。该启发式的语义召回率未知。
候选中仍有 **184 条没有完成逐条全文复核**；预览摘录只能用于排查，不能自动成为改标依据。因此目前不能声称“完整新版参照已冻结完成”。

同时，对六条已复核案例的完整政策原文，在全部 1,000 条中做了额外精确检索，不受上述长度阈值限制；命中仍为这六条，没有其他同政策原文案例漏纳。
特别是 H0108/H0998 使用完全相同的 Toyota 政策-only 原文，当前草案保持同一口径。

另对筛出的 **H0316** 完整阅读较短文档及长侧全部差异：两侧退款责任主体分别是 Brick Takeover GmbH 和 hapotec vertriebs limited，联系对象也不同。
这是实际政策义务主体冲突，不是“完整相同政策＋商品”，保留旧主决策并另存双侧精确证据作为负例开发保护候选；仍非新增独立 gold。

旧的两组完全相同文档对、方向归一后参照相反的问题仍存在：**H0177/H0634、H0053/H0739**。没有选某个版本的答案来替它们仲裁。
已导出 **227 条匿名待复核材料**，覆盖未复核增量候选、原 121 条中的剩余争议/待判断项、短政策边界及这两组矛盾。
这是复核材料集合，不是建议把 227 条直接作为新的在线实验面板，也不是穷尽所有潜在参照问题的保证。

## 最终结果：加权

所有版本使用同一旧参照、同一草案分别重算。括号内依次为 precision / recall / 主决策完全一致率。

| 版本 | 历史参照 | 五条主决策修订的部分草案 |
|---|---|---|
| v0.6.2.9 | 73.86% / 59.01% / 88.27% | **73.86% / 57.10% / 87.77%** |
| v0.6.2.12 | 67.99% / 77.59% / 88.28% | **67.99% / 75.07% / 87.78%** |
| v0.6.2.32 | 42.90% / 80.16% / 77.63% | **44.70% / 80.80% / 78.13%** |

.9 和 .12 原来都把这五条判成 NO，故其 precision 不变、recall 下降；.32 的五条答案符合本次应用建议，因此 precision 上升约 **1.80 个百分点**。
全部变化来自参照，没有新模型能力提升。没有一个版本在此部分草案下同时满足加权 precision、recall ≥75%；更不能据此宣布通过独立校准或 release gate。

| 版本 | 历史参照 P / R / 主决策一致率 | 部分草案 P / R / 主决策一致率 | 草案 over-group |
|---|---|---|---:|
| v0.6.2.9 | 76.76% / 53.43% / 84.60% | 76.76% / 52.15% / 84.10% | 33 |
| v0.6.2.12 | 74.44% / 81.37% / 87.60% | 74.44% / 79.43% / 87.10% | 57 |
| v0.6.2.32 | 52.29% / 83.82% / 77.10% | 53.82% / 84.21% / 77.60% | 151 |

非加权结果不能代替既定加权门槛。草案中的 .32 over-group 从 156 降为 151，远不足以解释或消除其退化。

## 同一主输出，critic 前后发生了什么

以下均使用同一份部分草案。main→final 包含 critic 及其仲裁/路由效应，不能解释成“单独升级 critic 模型的因果收益”。

| 版本 | main 加权 P / R | final 加权 P / R | 主决策改对 / 改错条数 | 主决策加权净变化 |
|---|---|---|---|---:|
| .9 | 64.16% / 78.27% | 73.86% / 57.10% | 37 / 39 | +1.01 pp |
| .12 | 63.17% / 86.24% | 67.99% / 75.07% | 21 / 16 | +0.57 pp |
| .32 | 44.38% / 80.80% | 44.70% / 80.80% | 3 / 0 | +0.29 pp |

- .9 critic 提高 precision，但丢失的真阳性权重为 **327.426**，recall 下降 **21.17 pp**。只看它较高的最终 precision，会漏掉主要代价。
- .12 critic 去掉误合并权重 **230.851**，同时丢失真阳性权重 **172.743**。它既有需要保留的修正，也有需要限制的误否决；不能简单全关或更强硬地全开。
- .32 critic 只修复两条误合并和一条方向错误。大部分误合并已经存在于主 Judge，继续只调 critic 不能视为已定位的整体解决方案。

“主决策改错”只计完全正确变错误；同组已经正确、但方向原本不全对的样本，若被 critic 进一步否决，也会损失 recall。因此它不等于所有丢失真阳性的数量。

## .32 剩余误合并的可审计归因范围

在草案的 151 条 over-group 上，复用原 121 条全文复核，并以最新短政策待核状态覆盖旧判断：

| 当前复核状态 | 条数 | 误合并权重 |
|---|---:|---:|
| AI 全文复核支持明确错误，未被本次政策更新挂起 | 75 | 781.147 |
| 原 121 条中的口径争议/待判断，含四条短政策待核 | 41 | 432.263 |
| 不在原 121 条增量复核范围，尚未按本轮逐条归因 | 35 | 332.826 |
| 合计 | 151 | 1,546.235 |

这三个集合互斥。第三项包含已知参照矛盾，不能全部归为模型错误。第一项也是 AI 开发复核，不是独立人工正确性证明。
该表只解释 .32 的误合并权重，不能拿它当作所有版本全部 precision/recall 缺口已经归因完毕。

## 下一轮建议

1. **以 .12 final 作实验对照，主 Judge 保持不变。** .9 保留为保守对照及负例保护来源；.32 保留作宽松包含边界的挑战输出，不继续在其上叠加规则。
2. 从本次 main→final 账本分开检查 .12 的 **21 条完整修正、16 条完整退化**，再补入方向原本有误但被进一步否决的样本。对存在参照争议的案例单列；没有独立标注前只能做开发诊断，不称为真实能力提升。
3. 小实验只改变 **critic 何时可以否决主 Judge**：完整保留政策且有新增商品不自动否决；真实政策责任主体、承诺覆盖或字段值冲突仍须拦截。同时保留已经修好的负例和已有 translation / chrome / identity 保护样本。
4. 先冻结新口径下的请求与评审材料；旧 48/64 条冻结及旧请求不覆盖、不直接冒充新协议。局部有配对收益且保护样本不退化，再回到完整 1,000 条在线评估；暂不启动 20,000 条。

按此草案作纯算术诊断：若 .12 的真阳性完全不损失，要达到 75% precision，需减少约 **159.709** 误合并权重，即当前 FP 权重的 **29.2%**。
其 recall 仅比 75% 高约 **0.07 pp**，几乎没有进一步误杀的余地。这不是可保证达到的修复收益，而是解释为何下一轮必须同时保护 recall。
