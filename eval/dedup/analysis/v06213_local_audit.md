# V0.6.2.13 修复与局部在线评估

## 结论

已实现新实验版本，完成 exact-only 的 1,000 条旧输出离线重放、20 条技术预检与 258 条局部在线评估。
**Exact 修复有效；.13 语义候选没有通过局部防回退条件，所以没有提交完整 1,000 条重评。**
完整 run root 仅准备了输入，未发起调用、未灌入局部预测、未复用旧缓存。
本轮未读取 holdout、运行 20,000 对、修改标签、标记 release 或提交/push 代码。

误合并与 false containment 明显减少，但真实扩展和 benign 保护损失过大。
不能将“误合并减少”或“测试通过”解释成修复完成、版本质量通过；也不能用跨运行拼接的反事实成绩替代在线候选。

## 实现与离线隔离

- `hs-v06213-exact` / `v7-exact`：沿用 .12 原 prompt/rubric，仅保护完整、非空、未截断、字面相同且主 ledger 已合法判双向的文本。
  不凭 token alignment 零差异保护 canonical，不绕过主 ledger 未决/冲突，不要求模型编造不存在的独有片段。
- `hs-v06213` / `v7`：同步更新 main/critic system、pair、YAML；增加独立 `record_scope`，区分具体记录、组织自身介绍、
  等价消息、模板附着、不同记录和列表成员；为 benign 覆盖 containment 增加全部 unique-span 引用检查。
- 旧 .9/v3 与 .12/v6 的全部 1,000 条 public 字段仍分别重放一致，旧资源、结果和 manifest 未改写。
- 新推理代码及版本/adapter 测试后全套 370 条通过；增加 scope/retained-conflict 报告矩阵测试后全套 **371 条通过**。
  Ruff 与适用的缓存 pre-commit 文件检查通过；没有创建/同步新环境。

单独 exact-only 重放只修正 H0417、H0810 两个主决策，其他主决策不变：

## 局部集合与权重审计

在线前冻结 258 条：旧 127 困难集、全部 54 translation、12 identical、6 canonical、39 参照 containment、
38 负例保护、.12 全部 57 误合并的并集。标签分布为 121 YES、136 NO、1 UNRESOLVED。
它有意富集错误，不是代表性抽样，局部 precision/recall 不能作为完整 1,000 条的估计。

`stratum_sample_n`，`sample_weight` 列为空。不能从该 selector 计算“加权”结果，否则会退化成未加权。
发现时尚未对 .13 局部结果计分；未改动正在运行的选择文件、manifest、样本或模型输入。

实际评分按 canonical pair ID 回连原冻结 1,000 条参照，逐字段核对语义标签和 taxonomy 一致，保留原始分层列，
保存为 `v06213_local_evaluation_labels.csv`。局部权重合计 **2,072.772211350298**。
这不是重打标签或调权重。具体修正说明见 `v06213_local_weight_audit.json`；设计文档/原 selector 保留原状，方便审计。

## 同一 258 条局部集的结果

下面三列使用完全相同的样本、原始权重和冻结参照。.9/.12 为原有运行中的对应样本，.13 为本次局部实测。

| 指标 | .9 | .12 | .13 |
|---|---:|---:|---:|
| 加权 duplicate precision | 61.46% | 49.02% | 70.23% |
| 加权 duplicate recall | 47.13% | 69.49% | 56.18% |
| 加权主决策一致率 | 68.21% | 61.18% | 66.92% |
| 未加权 duplicate precision | 68.00% | 62.75% | 81.13% |
| 未加权 duplicate recall | 42.15% | 79.34% | 71.07% |
| 未加权主决策一致率 | 61.63% | 67.05% | 71.71% |
| 误合并 | 24 | 57 | 20 |
| false containment | 4 | 22 | 3 |
| 参照重复漏判（含未决） | 70 | 25 | 35 |

.13 对 .12 修正 43 个参照主决策分歧，新增 31 个；142 个共同正确、42 个共同错误。
73 个当前分歧互斥分布：20 误合并、27 已决漏判、19 错误未决、7 个仅方向错误。
总计 20 个未决，其中 1 个与参照相符；8 个参照重复未决计入召回漏判，因此 27+8=35。

全部 54 translation 的主决策正确数仍是 52，加权一致率 89.81%，与 .12 相同；但错误成员/类型有变化，
不能声称逐条完全保留。12 identical 与 6 canonical 主决策全部正确。
39 个参照 containment 中漏判从 .12 的 17 个增至 27 个，不能只看 false containment 的下降。

## 逐例归因

| ID | 检查到的原因 | 属于哪一层 |
|---|---|---|
| H0017 | scope 已引用双侧身份，binding 只引用 B003 的新增社交媒体服务；新增 scope gate 又将原先保护的 additive translation 判未决 | 重复的引用适用性要求/仲裁 |
| H0878 | 主 Judge 正确识别新增排障步骤；critic 引用齐全却称其为“benign extension”，新仲裁因此抹掉新增步骤 | 覆盖引用不等于语义覆盖，benign 仲裁过宽 |
| H0333 | 主 Judge 和 critic 都把具体申请联系人/邮件标题指令混入反垃圾邮件 UI/翻译中 | 模型将实质指令误分类为 chrome；不是引用缺失 |
| H0038 | 主 Judge 正确认为重复模板加普通 Category 4 标签无害；scope 将该标签升级成独立记录，并覆盖了非正文等价 | scope 对非正文分支过度否决 |
| H0679 | 主 Judge、binding 和 retained 字段都认为 Payment 标签无害；scope 却选择 generic_context_only，最终产生未决 | critic 内部分类分歧与仲裁适用性 |
| H0553 | binding 已正确否决独立新闻附着；scope 没在自己的段落引用 unique span，新增 scope 将已有正确 NO/NO 改成未决 | 新辅助 proof 不应轻易抹掉已有合法否决 |
| H0072 / H0959 / H0964 | 仍把作者简介+其文章、活动介绍+相关法律更新、博客规则+评论，当作“同一页面的内容扩展” | 具体记录范围仍被页面/归属关系替代 |
| H0748 | 仅 Stories/作者名字仍被猜成具体故事或人物页 | 无可见事实支撑的角色推断 |

这些是基于保存文本和预测的开发归因，不是新的人工盲审。引用验证只能验证引用存在和范围完整，
不能自动证明“所有新增意义都被另一侧覆盖”；此次 H0878 是直接反例。

## 固定输出与跨运行对照

在相同 .13 main/critic 原响应上关闭 scope 仲裁、保留 exact/.12 路由：

| 仅改变仲裁 | 加权 precision | 加权 recall | 加权主决策一致率 | false containment |
|---|---:|---:|---:|---:|
| 无新 scope 仲裁 | 68.08% | 61.72% | 68.15% | 5 |
| 正式 .13 | 70.23% | 56.18% | 66.92% | 3 |

Scope 改变 16 个主决策：修正 6 个、损坏 7 个、另 3 个仍与参照不同。它本身就是新的风险来源，不能只继续加引用限制。

另做了三种跨运行原响应拼接，只用于归因、不是在线候选：

| 反事实组合（同一 258 条） | 加权 precision / recall | 真实 containment 保护 |
|---|---|---:|
| 新 main + .12 critic，不启用 scope | 56.05% / 70.77% | 3/4 |
| .12 main + 新 critic，不启用 scope | 62.42% / 62.70% | 4/4 |
| .12 main + 新 critic，启用 scope | 67.12% / 58.49% | 1/4 |

保留 .12 main 并关闭新 scope 能恢复 4 条保护方向，但全部负例仍仅 28/38，不能把它直接包装成通过的新版本。

## 下一步应如何收敛

本轮确定保留的增量只有 exact 的版本化修复。对语义候选，当前证据支持以下更窄的下一次实验，而不是扩大 .13 调用：

1. 撤回 scope 对已有合法 NO/NO、完整非正文等价和 additive-translation 保护的新增破坏；同一 critic 内的 scope/binding
   应分担明确的身份/差异证明任务，而不是重复要求每段都写齐相同引用。仍不能把缺失证明当成已证明负例。
2. 不再让“引用了全部 unique spans”单独授权 benign 覆盖真实扩展。需逐条指明对侧哪条内容保留了新增指令/事实；
   不能用“相关建议”“无害扩展”“没有冲突”替代语义覆盖证明。H0878、H0333 必须成为独立保护。
3. 收紧的对象应是实际独立内容/身份，而非文本长度或标签形状。对作者简介+文章、活动+相关更新、规则+独立评论，
   明确“相关/同一页面”不是同记录；同时保护仅分类标签、Payment、作者 teaser 的反例。
4. 新实验仍要先局部防回退；不得修改已评估 .13 的 prompt 或绕过失败条件直接跑完整集。
   全部 1,000 条的 75%/75%/79% 门槛及 38/4/5 保护集合保持不变。

原有 22 条扩展争议仍有政策/参照不一致，不按本轮预测改标签或删除样本来提高成绩。
最终如果要决定修改标签口径，应另行独立复审，不能把这里的开发归因宣称为人工确认。
